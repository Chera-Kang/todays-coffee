# Todays-Coffee Project Rules & Guidelines

이 문서는 '오늘의커피' (커피 큐레이션 및 영양성분 탐색 웹 서비스) 프로젝트의 개발 표준, 디자인 시스템, QA 테스팅 및 Git 버전 거버넌스 규칙입니다.

---

## 1. 기술 스택 및 데이터 아키텍처 (No-Backend)
- **Tech Stack**: React 19 (Vite) + Tailwind CSS v4 + Lucide React (라인 아이콘)
- **Data Source**: 별도 백엔드 서버 없이 `src/data/` 경로 아래 JSON 파일(`menus.json`, `beans.json`, `brands.json`)을 단일 진실 공급원(SSOT)으로 사용합니다.
- **로컬 검증 의무**: 코드 변경 후에는 반드시 `npm run dev` 빌드 및 로컬 구동에 에러가 없는지 검증합니다.

---

## 2. 디자인 시스템 및 UI/UX 원칙 (Anti-AI Cliché)
- **29CM / 화해 스타일의 에디토리얼 룩앤필**:
  - AI가 생성한 전형적인 템플릿 느낌을 철저히 배제하고, 여백과 타이포그래피(Pretendard Variable) 중심의 차분하고 감각적인 디자인(`Warm Cafe Minimalism`)을 유지합니다.
- **절대 금지 스타일**:
  - ❌ 파란색/보라색 계열의 그라데이션 배경 및 네온 컬러 버튼 사용 금지.
  - ❌ 텍스트나 제목에 기본 이모지(🔥, 🚀, ✨ 등) 도배 금지.
- **아이콘 및 에셋**:
  - 모든 아이콘은 `lucide-react`의 얇고 세련된 라인 아이콘으로 통일합니다.
- **반응형 뷰포트 & 모바일 네이티브 UX**:
  - 모바일 퍼스트 반응형 레이아웃, `dvh` 단위 모달 바텀시트, Safari 16px 줌 방지, 안드로이드 뒤로가기(History API) 제어를 준수합니다.

---

## 3. 향후 QA 테스트베드 연계 고려 (Testability Standards)
- **식별자 부여**: 주요 인터랙션 요소(브랜드 필터, 카테고리 탭, 추천 모달, 카드 클릭 등)에는 테스트 자동화(Playwright E2E)를 고려하여 명확한 `id` 또는 `data-testid`를 부여합니다.
- **시맨틱 마크업**: 표준 시맨틱 HTML 태그(`button`, `input`, `section` 등)를 사용하여 셀렉터의 견고성을 보장합니다.

---

## 4. 형상 관리(Git) 및 시맨틱 버전 거버넌스 (Semantic Versioning Rules)
> **상세 규약**: [git_rules.md](./git_rules.md) 전용 규칙을 100% 최우선으로 따릅니다.

1. **사전 승인 원칙 (Strict Authorization)**:
   - 체라님의 명시적인 요청이나 승인 없이 `git commit` 또는 `git push`를 절대 임의로 실행하지 않습니다.
   - 커밋 실행 전, 변경 파일 목록과 커밋 메시지 전문을 체라님께 먼저 보여드리고 확인을 받습니다.
2. **시맨틱 버전 기반 커밋 메시지 (`[MAJOR.MINOR.PATCH]`)**:
   - 커밋 메시지 선두에 프로덕트 버전 태그를 필수로 기재합니다.
   - **기본 포맷**: `[MAJOR.MINOR.PATCH] 작업 사유` 또는 `[MAJOR.MINOR.PATCH] 대체문구: 상세 내용`
   - **버전 증가 규칙**:
     - **시작 번호 (Baseline)**: 초기 5차 고도화 이후 첫 시맨틱 커밋은 **`[1.0.0]`** (정식 릴리즈 베이스라인)으로 선언합니다.
     - **PATCH**: 일상 수정/버그/테스트 코드 작성 시 1씩 자동 증가 (`1.0.1` ➔ `1.0.2` ...)
     - **MINOR**: `next_plan.md`의 마일스톤 배포 완료 시 마이너 증가 및 패치 0 리셋 (`1.0.x` ➔ `1.1.0`)
     - **MAJOR**: 대규모 아키텍처 개편 및 PWA 배포 시 (`2.0.0`)
   - **표준 대체문구**: `버그수정`, `코드개선`, `테스트구축`, `문서수정`
3. **에이전트 자동 추적**:
   - 체라님이 커밋을 요청하면, 에이전트가 직전 커밋 로그(`git log -n 5`)를 읽어 다음 버전 번호를 자동으로 계산하여 메시지를 제안합니다.
4. **브랜치 보호**:
   - `main` 브랜치에 대한 강제 푸시(`git push -f`)는 절대 금지하며, 과거 커밋 히스토리는 원형 그대로 보존합니다.
